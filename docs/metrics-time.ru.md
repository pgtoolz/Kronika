# Время записи, расчёты и карты активности

[English version](metrics-time.md) · [Указатель справочника](features.ru.md) · [Linux](metrics-linux.ru.md)

Снимок содержит значения, собранные в определённый момент. Обычное значение, например RSS — объём физической памяти процесса, показывает состояние в этот момент; накопительный счётчик, например число прочитанных байтов, позволяет вычислить скорость изменения между двумя снимками. В формулах `t₀` и `t₁` — время этих снимков в микросекундах с начала Unix-эпохи, `x₀ = x(t₀)` и `x₁ = x(t₁)` — значения поля. Тогда `Δt = (t₁ − t₀) / 1,000,000` — прошедшее время в секундах, `Δx = x₁ − x₀` — прирост, `R(x) = Δx / Δt` — прирост за секунду. Выбор пары снимков зависит от расчёта и описан ниже.

## Время и выбор данных

| Элемент управления или значение | Определение |
|---|---|
| Час в календаре | Интервал `[h, h + 3,600,000,000)` в микросекундах, где `h` — начало часа. Календарь и часы используют выбранный часовой пояс. |
| Курсор | Выбранное время внутри часа. Таблица берёт последний подходящий снимок не позже курсора. Источники с разными периодами сбора могут дать разные времена. Разделённые по базам секции PostgreSQL выбирают снимок каждой базы независимо. |
| Время снимка | Фактическое время выбранных данных. Общая подпись показывает именно его; выбор времени между снимками не создаёт нового измерения. |
| Предыдущее/следующее наблюдение | Переход по упорядоченному множеству времён текущего экрана без повторов. Выбранная метрика шкалы не задаёт шаг перехода. |
| Наведение на график | Показывает записанные точки. Выбор точки меняет общий курсор. Значение `null` разрывает линию графика. |
| Нажатие ячейки карты активности | Курсор переходит к правой границе ячейки минус одна микросекунда; затем таблица выбирает снимок. |
| Строка объекта | Открывает Inspector — панель подробностей этого объекта. Кнопка метрики выбирает поле его графика; линза — набор показателей, например CPU или Memory — меняет доступные поля. |
| Обновление текущего часа | Видимый текущий час обновляется каждые 15 секунд. Скрытая страница останавливает таймер, возврат к ней обновляет час. Курсор, следующий за последними данными, продвигается; выбранный вручную остаётся на месте. Завершённые часы периодически не обновляются. |

Период сбора задаётся в секундах. ## Правила пар и единицы

| Где рассчитывается значение | Выбор пары и причины недоступности |
|---|---|
| Скорости в таблице процессов | Тот же PID (номер процесса) в предыдущем снимке процессов и равный записанный `starttime`. Нет предыдущего снимка, изменилось время запуска, отсутствует значение поля, уменьшился счётчик или `Δt ≤ 0` — соответствующая скорость равна `null`. Равные счётчики дают ноль. |
| Сводка процессов | Складывает пригодные скорости отдельных процессов в каждом снимке. Для обычных значений складываются присутствующие числа. Без слагаемых метрика равна `null`; число процессов, готовых к работе процессов и процессов PostgreSQL может быть нулевым. |
| История процесса в Inspector | Соседние записанные значения выбранного поля и PID. Явный `null` сбрасывает предыдущее значение; отрицательная разность или неположительное прошедшее время дают `null`. В этой истории `starttime` не проверяется. |
| Скорости машины/контейнера на шкале | Соседние значения ряда счётчика. Отрицательная разность даёт `null` для пары; явный `null` сбрасывает предыдущее значение. |
| Вычисляемая история устройства/cgroup | Сначала вычитаются целые значения, затем результат преобразуется в число с плавающей точкой. Нет исходного значения, отрицательна разность компонента или неположительно прошедшее время — результат `null`. Для задержки нужен положительный прирост числа операций. |
| Итог счётчика на карте активности | Последнее значение минус первое для объекта в выбранном диапазоне. Нужны два времени и неотрицательная разность крайних значений. Это не сумма только положительных соседних приростов. |
| Health | Свои правила выбора ресурсов и предельного возраста снимка PostgreSQL, описанные ниже. |

В пределах часа процесс определяется числовым PID. Дополнительная проверка времени запуска `starttime` действует только для скоростей в таблице процессов и её сводке. Источники: [поля идентификации процесса](../crates/kronika-registry/src/codec/os_process.rs), [предыдущий снимок](../crates/kronika-query/src/snapshot/mod.rs), [суммирование сводки](../crates/kronika-query/src/hour/process_summary.rs), [история в панели подробностей](../bins/kronika-web/ui/src/detail.tsx), [скорости на шкале](../crates/kronika-query/src/hour/lanes.rs), [расчёты устройств](../bins/kronika-web/ui/src/system-view.tsx).

|---|---|
| CPU процесса | Записанные такты делятся на положительное записанное число учётных тактов в секунду `clock_ticks_per_sec`. Одна секунда CPU за секунду прошедшего времени означает одно занятое ядро. |

## Статистика графиков

Статистика показывает распределение значений каждой нарисованной линии. В расчёт входят только её конечные числовые значения: `null`, бесконечности и NaN исключаются. Каждое значение имеет одинаковый вес независимо от времени до следующего снимка. Пусть `n` — число значений, а `x₁ … xₙ` — они же по возрастанию. Для доли `q` процентиль выбирается по рангу: `p(q) = x[max(1, ceil(q × n))]`, где `ceil` округляет вверх; для P50, P90 и P99 берутся `q = 0.50, 0.90, 0.99`. `Min = x₁`, `Max = xₙ`; `Last` — последнее конечное значение по времени. Между значениями ничего не интерполируется. Если чисел нет, строка статистики отсутствует. Источник: [`seriesStats`, `chartStatsRows`](../bins/kronika-web/ui/src/uplot-chart.tsx).

## Карты активности

<a id="ячейки-и-ranking"></a>

### Ячейки и порядок строк

Карта активности показывает, кто внёс вклад в выбранный час и когда этот вклад был наибольшим. Час делится на 60 колонок для процессов, запросов, планов, баз данных, CPU и ввода-вывода cgroup; для таблиц и индексов — на 12. Пусть `h` — начало часа в микросекундах Unix, `C` — число колонок, `j` — номер границы от 0 до `C`. Тогда `bⱼ = h + floor(j × 3,600,000,000 / C)`, где `floor` округляет вниз. Ячейка `j` содержит время `[bⱼ, bⱼ₊₁)`: левая граница входит, правая — нет.

Наблюдение относится к колонке, в которую попадает середина интервала между ним и предыдущим наблюдением того же объекта. Для первого наблюдения используется его собственное время. Когда счётчик переходит в новую колонку, предыдущее значение переносится в расчёт этой колонки. Весь прирост относится к одной колонке: он не распределяется по времени между всеми пересечёнными колонками.

| Значение | Накопительный счётчик | Обычное значение (gauge) |
|---|---|---|
| Ячейка объекта | `(last − first) / elapsed_seconds`: последнее и первое значения ячейки, включая перенесённое предыдущее значение; знаменатель — время между ними в секундах | Последнее отнесённое к ячейке наблюдение |
| Порядок объектов и итог справа | Последнее значение минус первое за выбранный диапазон | Максимум за диапазон, кроме среднего RSS в режиме Grid ниже |
| Порядок групп | Сумма итогов объектов группы | Сумма итогов объектов группы |
| Ячейка группы | Сумма доступных ячеек объектов группы | То же |
| Ячейка Total («Всего») | Сумма доступных ячеек всех объектов | То же |
| Ячейка Other («Остальные») | Сумма для объектов или групп вне показанных строк | То же |
| Итог Total/Other справа | Сумма соответствующих итогов счётчиков | Максимум соответствующих сумм ячеек; для RSS Grid — сумма средних, описанная ниже |

Если нет ни одного слагаемого, результат равен `null`. Одного наблюдения счётчика недостаточно для скорости или итога. Итог счётчика проверяет первое и последнее значения; промежуточное уменьшение само по себе не отменяет итог всего диапазона. Режим запроса `RankingOnly` возвращает в `totals_total` наибольший индивидуальный максимум обычного значения; в режиме карты `Grid` итог Total — максимум суммы ячейки. Источники: [`Obs`, `Accumulator`, `column_of_span`](../crates/kronika-query/src/heatmap/execution.rs), [виды запросов](../crates/kronika-query/src/heatmap/query.rs).

### Среднее RSS Grid

Среднее RSS отвечает на вопрос, сколько резидентной памяти процесс внёс в общий объём за выбранное время. Для `os_process.rmem_kb` в режиме карты `Grid` обозначим через `T` множество различных времён, в которые запрос прочитал пригодное значение RSS хотя бы одного процесса; `N = |T|` — число таких времён. Для PID `p` среднее равно `meanRSS(p) = Σ recordedRSS(p,t) / N`, где сумма берётся по его записанным значениям RSS. Если PID отсутствует в определённый момент, он ничего не добавляет в числитель; знаменатель общий для всех PID. Итоги групп, Total и Other складывают эти средние. Для перевода KiB в байты результат умножается на 1,024. Вес снимков не зависит от промежутка времени между ними. Ячейки по-прежнему используют последнее отнесённое к ним значение. Режим `RankingOnly`, в том числе рейтинги MCP, использует максимум RSS. Источник: [`RssMean`, `score`, `additive_summary`](../crates/kronika-query/src/heatmap/execution.rs); [проверка результата RSS](../bins/kronika-web/src/tests/artifacts/heatmap_rss.rs).

### Выбор метрики, группировка и цвет

Процессы объединяются по записанному имени команды `comm`. Нажатие подписи группы передаёт это имя в поиск процессов. Объект получает группу при первом наблюдении в выбранном диапазоне. Подписи карт cgroup не фильтруют таблицу. Таблицы и индексы группируются на выбранном уровне отношений PostgreSQL. Компактная карта показывает восемь строк; развёрнутая — 10, 25, 50 или 100. Остальные строки входят в Other («Остальные»).

| Карта активности | Выбираемая метрика и её исходные поля |
|---|---|
| Processes — процессы | CPU: `utime + stime`; RSS: `rmem_kb`; чтение Read: `read_bytes`; запись Write: `write_bytes`; большие страничные промахи Major faults: `majflt`; ожидание CPU Run delay: `rundelay_ns` |
| Statements — запросы | Время выполнения Execution time: `total_exec_time`; вызовы Calls: `calls`; строки Rows: `rows`; прочитанные общие буферы Shared read: `shared_blks_read`; изменённые общие буферы Shared dirtied: `shared_blks_dirtied`; запись временных буферов Temp written: `temp_blks_written`; WAL: `wal_bytes` |
| Plans — планы | Время выполнения Execution time: `total_time`; вызовы Calls: `calls`; строки Rows: `rows`; Shared read: `shared_blks_read`; Temp written: `temp_blks_written` |
| Tables — таблицы | Изменённые строки Writes: `n_tup_ins + n_tup_upd + n_tup_del`; строки последовательного чтения Sequential read: `seq_tup_read`; чтение буферов таблицы Heap read: `heap_blks_read`; мёртвые версии строк Dead tuples: `n_dead_tup` (обычное значение); время autovacuum: `total_autovacuum_time` |
| Indexes — индексы | Сканирования Scans: `idx_scan`; прочитанные записи Tuples read: `idx_tup_read`; прочитанные блоки Blocks read: `idx_blks_read` |
| Databases — базы | Подтверждения Commits: `xact_commit`; откаты Rollbacks: `xact_rollback`; чтение Read: `blks_read`; временные байты Temp bytes: `temp_bytes`; взаимоблокировки Deadlocks: `deadlocks` |
| CPU группы cgroup | CPU: `usage_usec`; время ограничения квотой Throttled: `throttled_usec` |
| Ввод-вывод группы cgroup | Байты чтения/записи: `rbytes`, `wbytes`; операции чтения/записи: `rios`, `wios` |

Цвет показывает величину значения относительно выбранного максимума. Для положительного `value` ступень цвета равна `min(6, max(1, ceil(6 × sqrt(value / scaleMax))))`: `scaleMax` — максимум шкалы, `sqrt` — квадратный корень, `ceil` — округление вверх. Получается одна из шести ступеней. Ноль имеет нулевую интенсивность, `null` оставляет ячейку пустой. Общая шкала Global берёт максимум среди показанных строк и Other; построчная Row — максимум собственной строки. Total всегда использует свой максимум. Переключение меняет цвет, но не числа. Источники: [выбираемые метрики](../bins/kronika-web/ui/src/activity-cuts.ts), [группировка и управление](../bins/kronika-web/ui/src/activity.tsx), [цветовая шкала](../bins/kronika-web/ui/src/heatmap.ts).

## Health

Health показывает оценку нагрузки в целых процентах. Компонент OS зависит от времени, в течение которого задачи ждали CPU, память или ввод-вывод. PSI — записанные ядром показатели такого ожидания. Пусть `E = t₁ − t₀` — интервал в микросекундах; `S_cpu`, `S_memory`, `S_io` — приросты счётчика PSI `some_total` каждого ресурса, также в микросекундах. Берётся наибольший прирост, ограниченный длиной интервала: `W = min(E, max(S_cpu, S_memory, S_io))`. В формуле ниже `floor` округляет вниз.

`OS health = 100 − floor((100 × W + floor(E / 2)) / E)`.

Нужны все три показателя PSI и положительный интервал. Уменьшение любого счётчика даёт `null` для этой пары. Снимок PSI со значением `null` сбрасывает предыдущий снимок для расчёта. Для записи машины используются показатели всей машины (`scope = 0`), для контейнера — pod или контейнера (`scope = 1` или `3`). Записанный вид окружения и идентификатор загрузки ОС определяют эту область и допустимую пару снимков. При неоднозначных метаданных Health недоступен.

Компонент PostgreSQL сопоставляет число активных серверных процессов с доступными ему ядрами. `A` — число записанных строк `pg_stat_activity`, у которых состояние в точности `active`, включая активные служебные процессы. `C` — число доступных PostgreSQL ядер, допускающее дробь. Условная вместимость для расчёта равна `K = 2 × C`. Превышение этой величины задаёт вычитаемый штраф `PG penalty`:

`PG penalty = 0`, если `A = 0`; иначе `round(100 × max(A − 2 × C, 0) / A)`.

`PostgreSQL health = 100 − PG penalty`.

`round` округляет до ближайшего целого, половину вверх. Например, при `C = 8`
значения `A = 16` и `A = 20` дают Health `100` и `80`; при `C = 1.5` значения
`A = 3` и `A = 4` дают `100` и `75`.

Значение `C` выбирается на время каждого снимка PostgreSQL в следующем порядке:

| Источник | Значение `C` |
| --- | --- |
| Явное положительное `instance_metadata.postgresql_effective_cpus` | Записанное значение `KRONIKA_POSTGRES_EFFECTIVE_CPUS` (`1..4294967295`), заменяющее автоматический расчёт |
| Машина или VM без явного значения | Число различных `os_cpu.cpu_id ≥ 0` в последнем полном снимке CPU не позже снимка PostgreSQL; суммарная строка `cpu_id = −1` не учитывается |
| Контейнер без явного значения | Последний `os_cgroup_context` ресурсов сборщика не позже снимка PostgreSQL: положительная квота `Q`, делённая на положительный период `P`; результат ограничен сверху положительным `cpuset_cpus`, если это число разрешённых CPU записано |
| Контейнер с квотой `−1` | Положительное `cpuset_cpus`; без него `null` |
| Контейнер с отсутствующей или некорректной квотой/периодом | `null` |

`Q` и `P` — квота времени CPU и период её предоставления в микросекундах: `150000/100000 = 1.5` ядра. Запись cgroup уже учитывает самое строгое видимое ограничение родительских групп. Изменение квоты или снимка CPU влияет только на последующие снимки PostgreSQL. Для виртуальной машины не используется число групп управления частотой CPUFreq или объединение номеров CPU за весь сегмент. Если доступные ресурсы контейнера определить нельзя, результат остаётся `null`.

Без явного значения расчёт относит PostgreSQL к ресурсам той же машины или контейнера, где работает сборщик. Для PostgreSQL на другой машине или в другой cgroup число ядер нужно задать явно; это относится и к другой cgroup на той же машине. Строка подключения DSN, имя машины и PID не проверяют это условие размещения. `KRONIKA_PG_DSNS` включает сбор PostgreSQL. Если неизвестны число активных процессов или доступные ядра, результат равен `null`. Конфликтующие структуры записей активности в один момент оставляют число процессов неизвестным.

Health и отметки превышения числа активных процессов используют одно значение `C`. Расчёт читает записанные данные WAL/ZMS; ресурсы машины, на которой открыт просмотр, не участвуют. HTML-отчёт использует встроенную в него версию вычислений. Чтобы применить новую версию, отчёт нужно создать заново.

Общая оценка Overall вычисляется в моменты оценки OS. Для неё берётся последняя оценка PostgreSQL не позже этого момента, причём её возраст не должен превышать записанный период `postgresql_interval_seconds` в секундах:

`Overall health = max(0, OS health − PG penalty)`.

При отключённом сборе PostgreSQL штраф равен нулю. При включённом сборе неизвестные или слишком старые данные PostgreSQL дают `null` для общей оценки; неизвестная оценка OS также всегда даёт `null`. Флаги источников веб-сервера в расчёт не входят. Источники: [формулы](../crates/kronika-index/src/health.rs), [доступные ядра CPU](../crates/kronika-index/src/cpu_capacity.rs), [область ресурсов, число процессов и выбор времени](../crates/kronika-index/src/build.rs), [метаданные сборщика](../bins/kronika-collector/src/service_sections.rs).

## Отметки на шкале времени

Отметка на шкале позволяет перейти к исходному значению. Она хранит адрес: сегмент, физическую структуру записи, строку, поле, время и вид отметки. Вид `KnownBad` означает выполнение фиксированного условия. Условия для CPU, нагрузки, памяти, файловых систем, OOM и общей оценки перечислены в [метриках Linux](metrics-linux.ru.md#фиксированные-marks-и-цвета-cells). Для PostgreSQL действуют следующие условия:

| Источник | Условие отметки |
|---|---|
| Activity | Число активных строк `> 2 × C`; нужны известное `C` и однозначная структура записей активности в этот момент |
| Locks | Записанный список `blocked_by` непустой |
| Взаимоблокировки базы | Позднее значение `deadlocks` больше предыдущего для той же структуры записи и `datid` |
| Ошибки контрольных сумм базы | Позднее доступное `checksum_failures` больше предыдущего доступного значения той же базы и структуры; явный `null` разрывает пару |
| Аварийно завершённые сеансы базы | Положительный прирост `sessions_fatal` или `sessions_killed`; поля проверяются независимо для той же базы и структуры |
| Возраст идентификаторов транзакций базы | `frozen_xid_age ≥ 1,600,000,000` или `min_mxid_age ≥ 1,600,000,000`; поля проверяются независимо |
| Архиватор WAL | Позднее значение `failed_count` больше предыдущего |
| Группа медленных запросов из лога | Конечное `max_duration_ms ≥ 5,000`, то есть не менее пяти секунд |
| Группа ошибок из лога | Записанная категория `5` (`data_corruption`, повреждение данных) |

Отметка возраста идентификаторов транзакций использует фиксированную границу 1,6 миллиарда; текущие настройки заморозки и защитного vacuum сервера в неё не входят. Для отметки прироста счётчика нужны два значения с возрастающим временем. Вид `Event` указывает на строки шести индексируемых видов логов PostgreSQL: ошибки, checkpoints, autovacuum/autoanalyze, медленные запросы, ожидания блокировок и запуск/остановка сервера. Строка повреждения данных также получает отметку `KnownBad`. Адреса сортируются, повторы удаляются; на блок физической секции сохраняется не более 4,096 адресов, а число до ограничения хранится отдельно.

`Spike` / «Резкий рост» — зарезервированный вид адреса для совместимости с сохранёнными индексами. Текущее построение индекса не создаёт такие отметки и не рассчитывает порог резкого роста. Источники: [условия отметок](../crates/kronika-index/src/detect/direct.rs), [виды событий и блоки](../crates/kronika-index/src/detect/mod.rs), [виды адресов и предел](../crates/kronika-index/src/findings.rs).
