# Safari R1: состояние реализации и приёмки

Ветка: `research/safari-compat`, базовый коммит `ed98f23`.
Изменения пока находятся в рабочем каталоге; коммит и выпуск не выполнялись.
Требования: [консолидированная спецификация](safari-compat-plan.ru.md).

## Зафиксированные результаты

- `make ui-build && make ui-check`: 637 unit-тестов, typecheck, проверка фикстуры
  и воспроизводимость обоих встроенных HTML-артефактов прошли.
- `KRONIKA_CHROMIUM_CHANNEL=chrome npm --prefix bins/kronika-web/ui run test:browser:safari`:
  **12/12 тестов**, без пропусков; восемь конфигураций UI и два офлайн-прогона
  (с двумя родительскими тестами Node). Chrome `157.0.8103.51`, WebKit `26.0`.
  Локально явно выбран установленный Chrome, не bundled Chromium Playwright;
  в CI предусмотрен bundled Chromium.
- UI SHA-256: `0340eba05b16a24bf09ad1dd8408230e9968d778c5ae2114af0be8765bbc6e7b`.
  Сгенерированный отчёт: **4 943 905 байт**, SHA-256
  `3d27a7ceab077cfbc5ca3d4ed8829aeb9d5f2e62d508b794d803a2feb24bae5f`.
  Это полнофункциональная фикстура с настоящим WASM, не размерная приёмка.
- Прежний CDP-набор: **2/2** выбранных регрессий прошли — полный сценарий
  экспорта и MCP clipboard/focus. Для headless macOS helper сочетаний клавиш
  передаёт нативные editor commands: одного Ctrl/Meta+A было недостаточно,
  поэтому тест раньше дописывал время в середину строки вместо замены.
  Полный исторический CDP-набор этим выборочным запуском не покрыт.

## Автоматический браузерный набор

`make ui-browser-check` после `make ui-install` и установки Chromium/WebKit
закреплённой версии Playwright. См. [сборку](build.ru.md#регрессия-chromium-и-webkit).

Набор исполняет настоящий встроенный UI, серверные ответы на компактной фикстуре
и HTML, созданный CLI `kronika-report` из `standalone.zms`. Скачанные байты
сравниваются с подготовленным отчётом по SHA-256; офлайн-отчёт отдельно
запускает WASM через `file://`. Проверяются desktop 1440×1000, phone 390×844,
320×700 и tablet 1180×820 в обоих движках. Touch/pointer-события resize и
`pagehide` для проверки владения URL синтетические, не физические жесты/bfcache.

Логи Node test runner, trace ZIP, скриншоты отказов и хеши входов сохраняются
CI; локальные trace/input-файлы находятся в
`bins/kronika-web/ui/.browser-results/` и не коммитятся.

## Открытые условия полного раунда

- Native Safari macOS с обоими режимами клавиатурной навигации; Safari/iOS 16.4.
- Физические iPhone/iPad: клавиатура/auto-zoom, safe area, поворот, resize,
  VoiceOver, clipboard и полный export → Downloads/Files → offline.
- Маленький, согласованный типичный и зафиксированный крупный отчёт на
  устройствах: память, время и предел размера. Фикстура не задаёт лимит продукта.
- V-01…V-06: password manager, реальный clipboard и живой backend/proxy/cache,
  история/отмена, темы и временные зоны не считаются закрытыми новым smoke-набором.

Недоступные среды обозначаются BLOCKED; запуск headless WebKit не заменяет их
приёмку. Изменений backend, авторизации, CSP-политики, потоковой архитектуры или
поддержки старого Safari в продолжении работы не делалось.

## Развёртывание 192.168.0.20:8181 (2026-11-12)

Рабочее дерево ветки собрано на целевом сервере (Fedora 41, toolchain 1.96.0,
`x86_64-unknown-linux-musl`) и установлено без бэкапа по указанию владельца:
`sudo install -m 0755 …/debug/kronika-web /usr/local/bin/kronika-web`, хеш
`32be7580fab09360773c4d95ef85ecfde8242f3ceff947d8dbac7d3edab0fafa`.
Перезапущено теми же параметрами (`taskset -c 6,7`, `--storage-dir
/var/lib/kronika`, `--listen 0.0.0.0:8181`), лог — `/var/log/kronika-web.log`;
сборка осталась в `~/kronika-build`. Прежний бинарник (bf1f1cfb…, 17 ноября)
заменён; collector и данные не трогались.
Живая проверка UI против 8181: Chrome и WebKit, desktop/phone — выбор часа
фиксируется, Tab остаётся внутри экспорта, закрытие возвращает фокус, таблицы
данных рендерятся (40/22 строки), ошибок JS нет. Нативный Safari на Mac/iOS к
серверу ещё не подключался.
