# Safari: консолидированная спецификация раунда R1

**Статус:** реализация в ветке `research/safari-compat`; автоматическая приёмка выполняется. Наличие кода не означает прохождения всех критериев ниже. Native Safari, Safari/iOS 16.4 и физические устройства пока не приняты. Текущее покрытие и результаты: [статус R1](safari-r1-status.ru.md).
**База анализа:** состояние репозитория `ed98f23`.
**Цель:** обеспечить работоспособность основных сценариев Kronika в Safari на macOS, iPhone и iPad, включая автономный HTML-отчёт, и защитить исправления от регрессий.

## 1. Основание и правила консолидации

Входные материалы:

- **A:** [«Совместимость веб-интерфейса с Safari»](safari-compat.ru.md), полный аудит: JS/DOM, CSS, iOS, сервер, экспорт, офлайн-отчёт и процесс проверки.
- **B:** аудит браузерных сценариев `/tmp/kronika/safari-audit/report.ru.md`: production UI, desktop/phone/tablet-конфигурации, сгенерированный офлайн-отчёт, копирование и скачивание. Путь локальный и временный; необходимые для этого плана результаты перенесены ниже.
- Дополнительное чтение текущего кода в местах предлагаемых изменений. Оно уточняет границы реализации, но не заменяет браузерный прогон.

Приоритет определяется влиянием на пользователя, а не происхождением находки. Одинаковые проблемы объединены; различающиеся условия проверки сохраняются. Готовые фрагменты из аудитов — варианты реализации, а не обязательные патчи.

Различаем четыре состояния:

| Состояние | Значение для плана |
|---|---|
| Воспроизведено | Известен конкретный неработающий сценарий; нужна правка и регрессионный тест |
| Видно в коде | Известно ограничение реализации; проверка должна связать его с пользовательским сценарием |
| Зависит от окружения | Нужны определённая версия браузера, устройство, настройка или объём данных |
| Работало в проверенном сценарии | Сохраняем рабочее поведение; результат не переносится автоматически на другие условия |

Playwright WebKit не равен Safari.app; мобильная эмуляция не равна физическому iPhone/iPad. Результаты предыдущих аудитов являются исходной точкой, а не приёмкой будущих изменений.

## 2. Границы раунда

### Целевые браузеры и продукты

- Цель поддержки: **Safari 16.4+ на macOS и Safari на iOS/iPadOS 16.4+**. Это требование раунда, не утверждение, что нижняя граница уже испытана.
- Продукты: серверный веб-интерфейс и **сгенерированный** автономный HTML-отчёт через `file://`.
- Устройства и способы ввода: desktop с мышью/клавиатурой, iPhone с экранной клавиатурой, iPad с touch; отдельно iPad с трекпадом/клавиатурой, если он доступен.
- Chromium остаётся обязательным регрессионным браузером. Этот раунд не вводит новое обещание полной поддержки всех версий Firefox.
- Обычный HTTP по LAN остаётся допустимым режимом продукта. Отсутствие secure-context API должно включать предусмотренный fallback, а не ломать интерфейс.

### Что сохраняем

- Кастомные календари и существующие UTC/browser-time, RU/EN, DST и timestamp-контракты. Замена на нативный date/time input не входит в решение.
- Формат экспорта, авторизацию, обработку ошибок, прогресс передачи и полностью автономное открытие отчёта.
- Различие между модальным мобильным инспектором и немодальной desktop-панелью.
- Масштабирование страницы и доступность с клавиатуры/VoiceOver. Не использовать `user-scalable=no` или ограничение максимального масштаба.
- Модель безопасности: не ослаблять CSP, проверки Origin, cookie-политику или валидацию ради обхода браузерной проблемы.
- Текущую структуру приложения. Не вводить Safari UA-sniffing, новый UI-фреймворк или общий слой абстракций без необходимости.

## 3. Объединённая исходная картина

| Область | Что известно до исправлений | Решение в R1 |
|---|---|---|
| Основной пикер | В обоих аудитах WebKit закрывает поповер при `relatedTarget === null` до обработки выбора | R1-01 |
| Модальные окна | A описывает зависимость от Tab-порядка; B воспроизводит выход фокуса из экспорта и мобильного инспектора | R1-02 |
| Возврат фокуса MCP | B: после закрытия в WebKit активен `BODY`, а не кнопка открытия | R1-02 |
| Ввод времени | `inputMode="numeric"` не соответствует обязательным двоеточиям в `HH:MM:SS`; экранная клавиатура требует проверки на устройстве | R1-03 |
| Размер полей | Вычисленные 12–13px создают риск auto-zoom iOS; логин в проверенной конфигурации имеет 16px | R1-03 |
| Touch-resize | Таблица подключает только mouse-handler; у инспектора нет обработки `pointercancel` и `touch-action:none` | R1-04 |
| Viewport и CSS | Есть layout-viewport расчёты, `100vh` и safe-area зависимости; поведение меняется между версиями Safari | R1-05 |
| Хранилище | Getter `localStorage` вычисляется вне защиты; B воспроизводит пустой root при запрете getter | R1-06 |
| Обычный `file://` | A получил доступное хранилище; B открыл полноценный отчёт со штатным WASM и семью разделами | Сохранить, R1-06/07/09 |
| Скачивание | Маленький файл с немедленным revoke прошёл B; большой экспорт и системное сохранение на iOS не покрыты этим результатом | R1-07 |
| Копирование | HTTP-fallback прошёл B; ручное выделение и системные действия iOS остаются отдельными сценариями | V-01 |
| CSS/API минимум | Tailwind 4 и распаковка отчёта задают ориентир 16.4; отдельные CSS-различия остаются и выше этой границы | R1-05/08 |
| CSP и gzip | Production UI загружался с реальными хешами и gzip в обоих движках | Сохранить, V-04 |
| Проверки | Существующий браузерный путь ориентирован на Chromium; WebKit не является обязательным CI-gate | R1-09 |

## 4. Обязательные пакеты работ

### R1-01. Основной пикер дня/часа

**Где:** `bins/kronika-web/ui/src/hour-picker.tsx`, `bins/kronika-web/ui/tests/hour-picker.test.mjs`, браузерные тесты production-артефакта.

**Требование:** взаимодействие внутри поповера не должно закрывать его из-за особенностей получения фокуса кнопками. Внешний pointerdown, Escape и клавиатурный уход должны иметь явное, согласованное поведение.

**Границы реализации:** использовать существующие обработчики внешнего pointerdown/Escape; не считать `relatedTarget === null` самостоятельным признаком ухода наружу. Изменение `onBlur` не должно потерять закрытие при выходе Tab. Перенос фокуса из rAF сам по себе не считается гарантией поведения экранной клавиатуры iOS.

**Приёмка:**

- [ ] Выбор доступного дня, затем часа меняет диапазон ровно один раз; внутренний клик не теряется.
- [ ] Переключение месяца, Arrow/Home/End и недоступные ячейки сохраняют действующие контракты.
- [ ] Внешний клик и Escape закрывают поповер; Tab/Shift+Tab позволяют покинуть составной виджет без зависшего поповера.
- [ ] Escape возвращает фокус на trigger; внешний клик и Tab не перехватывают фокус обратно у выбранного пользователем элемента.
- [ ] Открытие/закрытие не создаёт скачков прокрутки, дублирующихся listeners или невидимого активного поповера.

### R1-02. Модальность и восстановление фокуса

**Где:** `bins/kronika-web/ui/src/export-dialog.tsx`, `bins/kronika-web/ui/src/inspector.tsx`, `bins/kronika-web/ui/src/mcp-connect.tsx`; связанные порталы и dismiss-handlers.

**Требование:** модальное окно удерживает фокус и исключает управление фоном; закрытие возвращает его к явному инициатору. Desktop-инспектор остаётся немодальным.

**Границы реализации:** учитывать фактически доступные и видимые элементы, фокус на контейнере и портальные дочерние виджеты. Не полагаться только на достижение последней кнопки нативным Tab-порядком. В проекте уже есть явное перемещение по Tab в `SearchHelp` (`bins/kronika-web/ui/src/table-filter.tsx`); использовать существующий подход там, где он подходит. Не блокировать активные порталы при изоляции фона.

**Приёмка:**

- [ ] Tab/Shift+Tab циклически обходят доступные элементы экспорта и модального инспектора при разных настройках клавиатурной навигации Safari.
- [ ] Скрытые/disabled-элементы не получают фокус; изменение состояния окна не выпускает фокус на фон.
- [ ] Вложенный календарь и другие порталы остаются доступны; Escape не закрывает сразу несколько уровней.
- [ ] MCP возвращает фокус на кнопку открытия даже когда клик по ней не изменил `activeElement`.
- [ ] Для удалённого/недоступного инициатора есть осмысленный fallback, без исключения.
- [ ] Desktop-инспектор не получает лишнюю focus trap; VoiceOver не предлагает элементы фона активного модального окна.

### R1-03. Ввод времени и мобильные поля

**Где:** `bins/kronika-web/ui/src/export-dialog.tsx`, `bins/kronika-web/ui/src/export-time.ts`, `bins/kronika-web/ui/src/table-filter.tsx`, `bins/kronika-web/ui/src/styles.css`, соответствующие тесты и локализация.

**Требование:** пользователь может очистить поле времени и целиком набрать допустимый `HH:MM:SS` экранной клавиатурой. Редактируемые мобильные поля не провоцируют нежелательный auto-zoom.

**Границы реализации:** первый вариант — обычный текстовый режим ввода при сохранении текущего формата и парсера. Не считать замену `numeric` на `tel` решением ввода двоеточия. Авторасстановка разделителей не обязательна для этого раунда. Для затронутых мобильных полей обеспечить computed font-size не менее 16px; desktop-плотность без необходимости не менять.

**Приёмка:**

- [ ] На iPhone можно очистить, набрать, вставить и исправить время; двоеточие доступно без обходного пути.
- [ ] Невалидное время отклоняется понятным сообщением; нет скрытого округления или изменения часового пояса.
- [ ] Поиск и время экспорта не вызывают auto-zoom; клавиатура не перекрывает активное поле и основные действия.
- [ ] RU/EN, UTC/browser-time и существующие DST-тесты сохраняются; пользовательский pinch-zoom не отключён.

### R1-04. Touch-resize таблиц и инспектора

**Где:** `bins/kronika-web/ui/src/entity-table.tsx`, `bins/kronika-web/ui/src/inspector.tsx`, `bins/kronika-web/ui/src/styles.css`.

**Требование:** оба механизма изменения ширины работают мышью и touch, корректно завершаются при отпускании и отмене жеста.

**Границы реализации:** для таблицы использовать поддерживаемый установленной библиотекой touch/pointer-путь; не переписывать механизм таблицы. Для инспектора обеспечить управление жестом, `pointercancel` и очистку listeners; pointer capture применять, если выбранный способ требует его. Блокировать прокрутку только на resize-ручке, не на всей таблице/странице.

**Приёмка:**

- [ ] Реальный drag пальцем меняет нужную ширину в допустимых пределах; соседняя область по-прежнему прокручивается.
- [ ] Mouse, touch и имеющееся клавиатурное управление не регрессируют.
- [ ] Отпускание за пределами ручки, `pointercancel` и закрытие/размонтирование панели прекращают resize и освобождают listeners.
- [ ] На iPad с доступным трекпадом/клавиатурой остаются пригодные для touch размеры элементов; эмуляция такого результата не заменяет устройство.

### R1-05. Видимая область, safe area и CSS поддерживаемых версий

**Где:** `bins/kronika-web/ui/src/index.html`, `bins/kronika-web/ui/src/styles.css`, позиционирование в `bins/kronika-web/ui/src/hour-picker.tsx`, портальные поверхности помощи, поиска, экспорта и инспектора.

**Требование:** открытая поверхность и её действия остаются достижимыми в видимой области, включая панели Safari, экранную клавиатуру, поворот и safe area.

**Границы реализации:** согласовать координаты якоря и viewport; учитывать изменения размера и, где нужно, смещения visual viewport. Не ограничиваться заменой одного чтения высоты. `viewport-fit=cover`, если используется, вводить вместе с защитой всех затронутых краёв. Для MCP-backdrop обеспечить рабочий фон без зависимости от наследования переменных в старых поддерживаемых Safari. Нулевой safe-area inset в headless не определяет геометрию iPhone.

**Приёмка:**

- [ ] При ширине 320px и типичных phone/tablet-размерах доступны контент, закрытие и основное действие каждой поверхности.
- [ ] Открытая/скрытая панель Safari, клавиатура, поворот и пользовательский zoom не оставляют поповер за пределами видимой области.
- [ ] Нет перекрытия вырезом/Home Indicator в портретной и альбомной ориентации; нет двойных safe-area отступов.
- [ ] В светлой/тёмной теме на нижней границе поддержки читаемы модальные окна, затемнение и выделения.
- [ ] Sticky-заголовки, виртуальные строки, прокрутка и графики не получают геометрических регрессий.

### R1-06. Работа без доступного persistent storage

**Где:** обращения к storage в `bins/kronika-web/ui/src/app.tsx`, `bins/kronika-web/ui/src/display-time.ts`, `bins/kronika-web/ui/src/export-dialog.tsx`, `bins/kronika-web/ui/src/export-range.ts`, `bins/kronika-web/ui/src/inspector.tsx`; связанные callers.

**Требование:** недоступность хранилища не превращает интерфейс или отчёт в пустую страницу.

**Границы реализации:** защищать получение `window.localStorage` вместе с операциями чтения/записи. Настройки по умолчанию и состояние текущей сессии достаточны; полноценный memoryStorage-адаптер не обязателен. Сохранять текущую валидацию сохранённых значений.

**Приёмка:**

- [ ] Отдельные тесты покрывают бросающий getter, отказ чтения, отказ записи и повреждённое значение.
- [ ] UI запускается, настройки меняются в текущем сеансе, экспорт и инспектор открываются без необработанного исключения.
- [ ] При доступном storage сохранение настроек продолжает работать.
- [ ] Сгенерированный отчёт открывается через `file://`; специальный тест отказа storage не подменяет обычный сценарий.

### R1-07. Экспорт, сохранение и большие офлайн-отчёты

**Где:** `bins/kronika-web/ui/src/export-dialog.tsx`, `bins/kronika-web/ui/src/export-download.ts`, `bins/kronika-web/ui/tests/export-download.test.ts`, генерация/загрузка отчёта в `crates/kronika-report/src/generator.rs`.

**Требование:** пользователь получает пригодный для открытия файл после подготовки/передачи; приложение не сообщает о подтверждённой записи на диск только на основании вызова `link.click()`.

**Границы реализации:** сначала пройти существующий полный путь на устройстве, затем изменить конкретное отказавшее звено. Проверять отдельно user activation после длительного ожидания, срок жизни Blob URL, имя файла и память. Если нужен новый жест, допустима явная кнопка «Скачать готовый отчёт». Если нужен отложенный revoke, связать срок жизни URL с проверенным сценарием и освобождением памяти, а не вводить произвольную задержку как универсальный фикс. Сохранить ошибки сервера, авторизацию и прогресс.

Перед размерными прогонами записать конкретные входы: маленький регрессионный файл, типичный отчёт из согласованных данных и максимальный размер, заявляемый по результатам раунда. Если пользовательский верхний размер не задан, измерить возрастающие объёмы на целевом устройстве и явно ограничить вывод испытанным объёмом; не заявлять неограниченную поддержку.

**Приёмка:**

- [ ] На macOS Safari и iOS файл находится через системный интерфейс сохранения/Files, имеет ожидаемое имя и непустое корректное содержимое.
- [ ] Пройдены быстрый экспорт и экспорт после ожидания, превышающего обычный интервал transient activation; один жест не создаёт дубликаты.
- [ ] Повтор, ошибка передачи, истечение сессии и закрытие диалога не оставляют неконтролируемое накопление Blob URL/обработчиков.
- [ ] Маленький, типичный и зафиксированный крупный отчёт скачиваются и затем отдельно открываются; записаны размер, устройство, длительность и результат.
- [ ] Сгенерированный офлайн-отчёт запускает WASM, открывает основные разделы и графики без внешних сетевых запросов.
- [ ] Ограничение памяти/размера, если обнаружено, становится явным ограничением или отдельной задачей; не скрывается статусом «экспорт успешен».

Переход к нативному прямому скачиванию, поддержка HEAD/Range и потоковая переработка архитектуры не являются автоматической частью R1. Если без них невозможно выполнить согласованный сценарий, это отдельное решение об изменении объёма работ.

### R1-08. Контракт поддержки и понятный отказ

**Где:** пользовательская документация, entry/bootstrap серверного UI и отчёта в необходимом объёме.

**Требование:** документировать целевой минимум Safari/iOS 16.4 и ограничения реально проведённых проверок. При отсутствии обязательной возможности, которую можно обнаружить до её использования, показывать понятную ошибку вместо молчаливого сбоя; в первую очередь это запуск офлайн-отчёта и `DecompressionStream`/WASM.

**Границы реализации:** feature detection вместо UA-sniffing; не требовать от онлайн-UI API, используемое только офлайн-отчётом. Не добавлять полифиллы старого Safari и не обещать запуск диагностического кода в браузере, который не способен разобрать сам бандл.

**Приёмка:**

- [ ] Пользователь видит требования к браузеру и знает, что обновить при отсутствии обязательной возможности.
- [ ] Тест отсутствующего обязательного API не заканчивается только пустым root/ошибкой в консоли.
- [ ] Сообщения доступны в RU/EN и не перекрывают нормально работающую конфигурацию.

## 5. Дополнительные сценарии: проверить и исправить при отказе

Эти пункты входят в проверку R1, но не предписывают заранее менять рабочий код. Если сценарий поддерживаемой конфигурации не проходит, фиксируется конкретное исправление с регрессией. Изменение архитектуры или безопасности требует отдельного решения, а не молчаливого исключения теста.

| ID | Проверка | Условие приёмки |
|---|---|---|
| V-01 | Копирование через HTTPS и HTTP по LAN, основной Clipboard API и fallback, ручное выделение/Copy на iOS, help/tooltip с blur | В целевое поле вставляется точный текст; при реальном отказе доступен ручной путь, не исчезающий до завершения действия |
| V-02 | Safari AutoFill/менеджер паролей, логин/logout/refresh, переход по внешней ссылке, истечение сессии, прокси HTTPS и обычный HTTP | Успешный вход и понятная ошибка; не появляются неожиданные Basic-auth окна; не ослаблены Origin/CSP/cookie-проверки |
| V-03 | Полночь `00:00`, граница дня/месяца, UTC/browser-time, RU/EN, DST и зоны `Australia/Lord_Howe`, `Pacific/Apia`, `America/Sao_Paulo` | Метки, доступные часы, диапазон экспорта и выбранные timestamps согласованы; нет скрытого сдвига или потери DST-неоднозначности |
| V-04 | Живой сервер: gzip/identity, CSP, обычный reload и conditional reload с валидной кэш-записью, обновление сборки | Загружается актуальный UI, нет CSP/декодирующего отказа; искусственный 304 без кэша не используется как сценарий приёмки |
| V-05 | Светлая/тёмная тема, `::backdrop`, поиск и его cancel-кнопки, sticky/виртуальные строки, загрузка шрифтов, overlay-scrollbars | Контент и действия читаемы/доступны, измерения и прокрутка корректны; допустимые косметические различия зафиксированы |
| V-06 | Повторная навигация/Back/Forward, drag timeline, смена фильтров, refresh и отмена запросов на живом backend | Нет history-исключений, потерянного состояния и необработанных ошибок; намеренно скрытый мобильный preview не считается отказом |

Для V-02 отсутствие настоящего менеджера паролей, для V-04/06 отсутствие живого backend, для iOS-сценариев отсутствие устройства отмечаются как BLOCKED, а не заменяются успехом фикстуры. Проверку многодневных политик ITP этот раунд не обещает.

## 6. Матрица приёмки

| Среда | Обязательный объём | Что результат не доказывает |
|---|---|---|
| Chromium, production UI | Автоматический регрессионный набор и текущие тесты | Совместимость Safari |
| Playwright WebKit desktop + phone/tablet-конфигурации | То же, включая фокус, touch-handler и отчёт | Системное сохранение, экранную клавиатуру, safe area физического устройства |
| Native Safari на macOS, текущая доступная версия | Основные сценарии, два режима клавиатурной навигации, экспорт, clipboard, offline, V-02/04/06 | Работу нижней границы 16.4 |
| Safari 16.4 / iOS 16.4, доступное native-окружение | Запуск UI/отчёта, ключевые взаимодействия, CSS/fallback и обязательные API | Поведение более поздних версий без регрессий |
| Физический iPhone | Клавиатура/auto-zoom, viewport, safe area, копирование, полный export→Files→offline, VoiceOver для модальных сценариев | Поведение iPad и других объёмов памяти |
| Физический iPad | Touch-resize, панели, поворот, export/offline; трекпад/клавиатура при наличии | Все сочетания аксессуаров и размеров отчётов |

Размеры автоматических viewport: как минимум 320px, phone 390×844, tablet 1180×820 и desktop 1440×1000. Это размеры стенда, не замена устройств. Для physical-проверок фиксируются модель, версия ОС/браузера, ориентация, настройки навигации и размеры тестовых отчётов.

Формат протокола: `ID сценария | commit/артефакт | браузер/устройство | входные данные | ожидаемо | фактически | PASS/FAIL/BLOCKED | ссылка на лог/скриншот`.

Если Safari 16.4 недоступен, это остаётся явным пробелом: либо организовать проверку, либо отдельно согласовать другую подтверждённую нижнюю границу. Запуск современного WebKit не закрывает эту строку.

## 7. Порядок выполнения

1. **Базовая регрессия и доступность сред.** Закрепить тестовые данные и версии; проверить доступ к native Safari/iOS; перенести минимальные воспроизведения в production-артефактный runner. Существующий focus-probe оставить вспомогательным, не единственным тестом.
2. **Основные взаимодействия.** R1-01/02: пикер, модальность, возврат фокуса. После каждого исправления — Chromium/WebKit-регрессия.
3. **Мобильный ввод и геометрия.** R1-03/04/05, затем соответствующие device-проверки.
4. **Надёжность и экспорт.** R1-06/07/08; V-01…V-06, размеры отчётов и обычный `file://`.
5. **Интеграция.** Завершить R1-09, пересобрать артефакты, пройти канонические проверки и полную матрицу. Записать оставшиеся ограничения.

Каждый рабочий коммит должен включать затронутые callers, тесты и необходимые артефакты; не оставлять исправление только в исходниках при старом встроенном HTML. Коммит/публикация выполняются по отдельному поручению, этот документ их не запускает.

Существующие команды из корня репозитория:

```sh
make ui-build
make ui-check
npm --prefix bins/kronika-web/ui run test:browser:artifact
make report-assets-check
```

Команда нового WebKit-набора определяется при R1-09 и документируется вместе с CI. При изменении генератора/серверного кода добавляются соответствующие Rust-тесты; при изменении WASM/bindings — канонический `make report-assets` и повторная проверка. Команды требуют проектных версий инструментов и браузеров, а не случайного глобального окружения.

## 8. Что не делаем автоматически

- Поддержку Safari ниже 16.4: полифиллы `Object.hasOwn`/`.at()`/AbortSignal, fallback для старого MediaQueryList, переделку Tailwind и распаковщик для старого Safari.
- Смену кастомных календарей, формата времени/экспорта или библиотеки UI.
- Изменение `SameSite=Strict`, проверки Origin, CSP, ETag/Vary, заголовков 304 или кэш-политики без конкретного сценария и отдельной проверки безопасности/HTTP-контракта.
- HEAD/Range, новый транспорт экспорта, streaming-WASM и поддержку произвольно больших отчётов «на всякий случай».
- Переписывание работающего Clipboard fallback, общий рефакторинг всех focus-handler или бессрочное удержание Blob URL.
- Отдельный редизайн иконок, scrollbars и тем. Косметика включается в исправление только при нарушении читаемости/доступности либо как явно согласованный дополнительный пункт.
