# Сбои хранения и восстановление

[English version](storage-recovery.md) · [Сервисы](services.ru.md)

| Файл | Назначение | Кто записывает |
| --- | --- | --- |
| `active.wal` | Текущие данные, ещё не сохранённые в готовый сегмент. Это не WAL PostgreSQL. | Сборщик |
| `YYYY/MM/DD/<segment-id>.zms` | Готовая сжатая запись. | Сборщик; `kronika-dump slice` может создать отдельный ZMS. |
| `.idx` рядом с ZMS | Поисковый индекс, построенный по записи. | Веб-сервер |

## Как посмотреть ошибку

Начните с журналов работы и просмотра записей без изменения файлов:

```sh
sudo journalctl -u kronika-collector -u kronika-web --since '10 minutes ago'
sudo kronika-dump /var/lib/kronika
sudo kronika-dump /var/lib/kronika --json
sudo kronika-dump /var/lib/kronika --section 1100001 --limit 10
```

Укажите свой каталог хранения. Команды используют сервисы из
[руководства systemd](services.ru.md). Ошибки сборщика называют операцию;
события сегментов содержат `segment_path`. Ошибки API веб-сервера включают
причину сбоя чтения. Предупреждения каталога указывают активный журнал или
сегмент, иногда без полного пути. ID сегмента соответствует
`YYYY/MM/DD/<segment-id>.zms`.

`kronika-dump` проверяет структуру файлов и контрольные суммы секций.
`--section` также разбирает указанный тип и нужные словари; пример выводит
до 10 строк на сегмент. Ошибка разбора даёт ненулевой код завершения.
**Предупреждения возможны и при коде 0:** читайте stderr либо записи
предупреждений в stdout с `--json`. Фраза `set aside` означает исключение
из обхода, а не перемещение файла.

Если повреждённый файл мешает запуску, сохраните его перед дальнейшим разбором.
Повторный запуск не исправляет повреждение. Команды для восстановления
потерянных байтов WAL или ZMS нет. [Извлечение интервала](../bins/kronika-dump/README.ru.md)
позволяет отдельно сохранить читаемые данные, но не исправляет исходный файл.

## После внезапной остановки сборщика

Запустите сборщик обычной командой. Он сразу преобразует исправный непустой
`active.wal` в ZMS и продолжит сбор. `SIGINT` и `SIGTERM` оставляют журнал
для такого восстановления, не закрывая итоговый ZMS при остановке.

OOM kill и `SIGKILL` могут прервать запись. Журнал может остаться исправным
или содержать неполную порцию данных. То, что ещё не попало в журнал,
восстановить из него нельзя. Часть порций может сохраниться, даже если цикл
сбора не закончился. При отключении питания сохранность также зависит
от файловой системы и накопителя.

## Что сборщик делает при запуске

| Состояние журнала | Результат |
| --- | --- |
| Файл отсутствует или пуст | Создаётся пустой журнал. |
| Исправный непустой журнал | Сохраняется ZMS с записанным ID сегмента, журнал очищается, начинается новый сегмент. |
| Неполные данные, несовпадение длины или контрольной суммы | Запуск прекращается, `active.wal` сохраняется. Повреждённый хвост не отбрасывается, исправное начало не сохраняется отдельно. |
| Нечитаемые данные Parquet, неизвестный тип или несовместимая схема | Создание сегмента завершается ошибкой, журнал сохраняется. |
| Превышен настроенный размер или предел числа порций в формате | Журнал не открывается и не обрезается. |
| Подтверждена прерванная очистка журнала | Очистка завершается. Это не исправляет другие повреждения. |

Если ZMS по восстановленному пути уже существует, он должен пройти проверку
и побайтово совпасть с восстановленным файлом. Другой файл не перезаписывается.

После успешной очистки журнала появляется `wrote <path> reason=recovered`,
после подготовки сборщика — `ready`. Событие `segment_write_finish` с
`reason=recovered` и `segment_path` появляется раньше и само по себе не
подтверждает успешную очистку. При сбое записываются `segment_close_failure`,
`reason=recovered` и этап `write` либо `journal-reset`. Сообщение
`open active.wal; the existing file is preserved on failure` означает ошибку открытия.

## Чтение журнала во время сбора

Запрос читает завершённые порции, доступные в момент его начала, без последующих
добавлений. Очистка или замена журнала может прервать чтение. Во время записи
активный журнал может ненадолго исчезнуть из нового списка сегментов;
готовые записи остаются доступны. Прежде чем считать файл повреждённым,
повторите чтение после завершения текущего сбора. **Веб-сервер никогда
не обрезает, не очищает и не исправляет `active.wal`.**

## Когда проверяются готовые записи

Наличие файла в каталоге не означает, что все его данные читаются:

| Операция | Проверки |
| --- | --- |
| Получение каталога веб-сервером | Структура файла и контрольная сумма каталога, без чтения содержимого секций. |
| Список с проверкой данных, в том числе обычный `kronika-dump` | Структура и контрольные суммы всех секций выбранных готовых сегментов. Содержимое файлов вне выбранного интервала не проверяется. |
| Чтение секции | Её контрольная сумма, схема, число строк и ограничения разбора. Строки и нужные словари разбираются по мере чтения; остальные секции целиком не проверяются. |

Повреждённый каталог может скрыть файл целиком. Ошибка в секции может проявиться
только при открытии таблицы или графика, которым нужны эти данные. Контрольные
суммы обнаруживают изменённые байты, но не восстанавливают их.
[Справочник формата](../crates/kronika-format/README.ru.md) описывает расположение
данных и ограничения проверки.

## Отсутствующие и повреждённые индексы

Веб-сервер автоматически перестраивает отсутствующие, устаревшие или неверные
локальные `.idx`, в том числе индексы без нужных запросу блоков. Для этого нужны
читаемый ZMS и право записи в каталог хранения. Если индекс не открывается
из-за прав доступа или ошибки файловой системы, запрос может завершиться
до перестроения — сначала проверьте эти ошибки.

Индекс может отвечать на часть сводных запросов по повреждённому ZMS, но не
восстанавливает его строки. HTML-отчёт проверяет встроенный индекс и не
перестраивает его в браузере. Повреждённый отчёт создайте заново из читаемых записей.

## Что возвращает веб-запрос

| Ошибка | Результат |
| --- | --- |
| Неверный или недоступный файл при обходе каталога | Файл может исключаться с предупреждением, остальные записи доступны. Ошибка доступа к корню или обхода хранилища может прервать весь запрос. |
| Данные не читаются до начала ответа | HTTP `500`, `{"error":"unreadable"}`. |
| Сегмент или секция отсутствует | HTTP `404`, `{"error":"no_such_segment"}` либо `{"error":"no_such_section"}`. |
| Ошибка чтения после начала ответа | Передача обрывается без завершающей строки NDJSON с ошибкой. Полученные строки неполны, даже если HTTP-статус был успешным. |
| Предупреждение о неверном ZMS или активном журнале при экспорте HTML | HTTP `500`, `export_failed`, даже если проблемный файл находится вне запрошенного интервала. |
| Ошибка чтения названия экземпляра | Ошибка записывается в лог; HTTP `200` возвращает `database: null`. |

При допустимой для повтора ошибке изменения файла веб-сервер повторяет чтение
один раз до отправки ответа. Ошибки контрольной суммы и разбора так не повторяются.
После начала передачи ответ обрывается, чтобы не смешивать версии файла.
Браузер один раз повторяет прерванную сетевую передачу, но не запрос с ошибочным
HTTP-статусом.

Ошибки запросов не останавливают веб-сервер. Интерфейс сообщает о сбое загрузки
часа или таблицы и может оставить прежние строки; сбой обновления сохраняет
рабочий вид. Некоторые дополнительные ошибки видны только в консоли браузера.
Предупреждения каталога не открывают панель ошибки: если записи пропали,
проверьте журналы работы.

## Резервная копия перед разбором сбоя

Перед копированием хранилища остановите сборщик и веб-сервер либо сделайте
согласованный снимок файловой системы. Сохраните всю иерархию каталогов.
`active.wal` и ZMS — исходные данные, IDX можно построить заново. Состояние
чтения журналов PostgreSQL хранится вне каталога данных; если оно нужно для
восстановления, скопируйте его отдельно на тот же момент.

Для каждого каталога запускайте один сборщик. Не обходите защиту владения
хранилищем ради запуска второго. [Справочник хранения](../crates/kronika-layout/README.ru.md)
описывает владение каталогом, сохранение файлов и гарантии поддерживаемых
файловых систем.
