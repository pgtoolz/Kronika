# История изменений

[English version](changelog.md)

## [1.2.2](https://github.com/pgtoolz/Kronika/releases/tag/v1.2.2)

- Исправлена остановка сбора логов PostgreSQL на сообщениях без префикса или корректного времени. Распознанные сообщения без корректного времени сохраняются со временем чтения.
- В логах PgBouncer сохраняются неизвестные предупреждения, ошибки и события жизненного цикла с PID, стороной соединения, портом и возрастом. Штатные сообщения о соединениях пропускаются.

## [1.2.1](https://github.com/pgtoolz/Kronika/releases/tag/v1.2.1)

- Исправлено обновление при возврате во вкладку после завершения выбранного часа.
- Исправлено ручное и автоматическое обновление карт Activity.
- Cgroup собираются только в контейнерах с cgroup v2.
- Если ядро сообщает, что PSI не поддерживается, сборщик выводит одно предупреждение и прекращает чтение PSI до перезапуска.
- Веб-сервер по умолчанию показывает все источники.

## [1.2.0](https://github.com/pgtoolz/Kronika/releases/tag/v1.2.0)

### Сбор и настройка

- Сборщик, веб-сервер, dump, report и демонстрационная программа для разработки переведены на clap: `-h` выводит краткую справку, `--help` — подробную. Параметры командной строки сборщика, веб-сервера и demo имеют приоритет над переменными окружения. Лимиты хранения сборщика принимают размеры вроде `64MiB` и `10GB`; число байтов без суффикса также поддерживается. Десятичные суффиксы используют степени 1000, суффиксы IEC — степени 1024.
- Группы источников PostgreSQL собираются с отдельными интервалами. Значения по умолчанию: 30 секунд для счётчиков и настроек сервера, 10 секунд для активности, ожиданий блокировок и хода VACUUM, 5 секунд при обнаруженных ожиданиях блокировок, 300 секунд для statements/plans и таблиц/индексов. См. [интервалы сбора](bins/kronika-collector/README.ru.md#интервалы-сбора).
- Сборщик и веб-сервер используют по два рабочих потока Tokio. В musl-сборке коллектора jemalloc по умолчанию не использует Transparent Huge Pages (THP).

**После обновления:** `KRONIKA_PG_INTERVAL_S` задаёт интервал только для счётчиков и настроек сервера (`--pg-instance-interval-s`). Для активности и statements/plans используйте `KRONIKA_PG_ACTIVITY_INTERVAL_S` / `--pg-activity-interval-s` и `KRONIKA_PG_STATEMENTS_INTERVAL_S` / `--pg-statements-interval-s`. Минимальный интервал для statements/plans — 300 секунд; отсчёт начинается после завершения прохода сбора PostgreSQL, включавшего их чтение. `SIGUSR2` не обходит этот интервал.

### Веб-интерфейс и отчёты

- Стрелки навигации переходят между записанными снимками для текущего экрана, в том числе через границы сегментов, с шагом не менее секунды. Для выбранного времени экран получает последний снимок не позже курсора, включая данные из перекрывающихся сегментов. Это работает в веб-интерфейсе и автономных отчётах; в API добавлен [`/api/snapshot/neighbor`](bins/kronika-web/README.ru.md#endpoints).
- Карты активности Statements и Plans используют 12 столбцов на час — по пять минут, как Tables и Indexes. Ближайшие снимки за границами диапазона могут дополнять крайние столбцы. Поиск снимков за границами диапазона и промежуток между значениями счётчика ограничены 15 минутами; по более длинным промежуткам скорость не вычисляется. Допустимая нулевая разность остаётся нулём, а итоги ранжирования по-прежнему используют только крайние значения внутри диапазона. См. [временную семантику карт активности](docs/metrics-time.ru.md#heatmaps).
- Браузерный кеш API разделён по сборкам сервера. В справке показаны версия сервера и, если известен, коммит сборки.
- Обновление повторяет зависшие запросы, не отменяя потоки, по которым продолжают поступать данные; ответ отменённого запроса не заменяет текущий экран. Загрузку снимков можно восстановить, а шкала времени различает загрузку, ошибку и отсутствие данных. Исправлено создание графика до появления измеримых размеров его контейнера.

### Библиотеки и сборка

- Общий код чтения источников перенесён в `kronika-source-os` и `kronika-source-pg`, запросы и создание отчётов — в `kronika-report`, извлечение записей — в `kronika-slice`. Командная строка и серверная часть остаются в приложениях. См. [границы библиотек](crates/README.ru.md).
- Ресурсы отчётов собираются на эталонном Linux-хосте с закреплёнными версиями Rust, wasm-bindgen и Clang. Проверки воспроизводимости охватывают встроенные HTML и WebAssembly.

**Сборка из исходников:** для программы создания отчётов используйте `cargo build -p kronika-report-cli`. Исполняемый файл по-прежнему называется `kronika-report`; пакет Cargo `kronika-report` теперь содержит общую библиотеку.

## [1.1.0](https://github.com/pgtoolz/Kronika/releases/tag/v1.1.0)

- Добавлен `KRONIKA_PG_DSN` — строка подключения к PostgreSQL. Для сбора с нескольких серверов запускайте `kronika-collector` для каждого сервера, указав его `KRONIKA_PG_DSN` и отдельный каталог `KRONIKA_STORAGE_DIR`.
- Сборщики закрывают ZMS по расписанию со случайным сдвигом по времени. Этот сдвиг сохраняется после перезапуска; одновременные закрытия возможны.

Перенесите первое подключение из `KRONIKA_PG_DSNS` в `KRONIKA_PG_DSN` и удалите старую переменную. Поддержка `KRONIKA_PG_DSNS` будет удалена.

### Другие изменения

- Добавлен `KRONIKA_COLLECTOR_MODE=postgresql` для сбора данных локального или удалённого PostgreSQL без метрик Linux. В режиме `local` доступны метрики Linux той же VM или pod и, при необходимости, PostgreSQL. См. [настройки сборщика](bins/kronika-collector/README.ru.md).
- Добавлен сбор всех видимых и доступных групп cgroup v2. Их CPU, Memory, I/O и Tasks показаны в таблицах с поиском, сортировкой и историей. Данные групп разделены; отсутствие лимита отличается от недоступного значения. Старые записи по-прежнему читаются.
- Исправлено чтение записей PostgreSQL 12 и старых версий `pg_stat_statements`: отсутствующие поля не запрашиваются. Показатели Activity, которых нет в записи, скрыты.
- В HTML-отчётах за неполный час Activity занимает только записанный интервал. Клик по ячейке и переход к строке выбирают соответствующее время, а не начало отчёта.
